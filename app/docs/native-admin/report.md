# 앱 내부 관리자 화면 · 2026-11-15

관리자 계정으로 로그인한 뒤 **내 정보 → 관리자 페이지**를 누르면 Flutter의 수집 관리 화면이 열린다. 앱의 기존 로그인 토큰을 사용하며 별도 웹 로그인이 필요 없다.

## 실제 검증

- 기존 팀 서버의 컴파일 결과를 읽어 별도 Java/Spring Boot 프로세스로 실행했다. 별도 MariaDB 12.2 인스턴스·포트·작업 폴더에 기존 SQL을 적용했다. 팀 소스·기존 DB에는 쓰지 않았다.
- 기존 가입 API로 만든 합성 계정을 임시 DB에서만 관리자 지정했다. Android에서 로그인 토큰으로 DB·후기 조회, 출처 추가 후 재조회·삭제, 참고시간 재집계, 초기화 대상 velog 2건·티스토리 1건 확인, 취소 시 건수 유지, 명시적 확인 후 0건을 확인했다. 일반 토큰 403·인증 없는 요청 401과 일반 회원 메뉴 숨김도 확인했다. 검증용 관리자 지정은 이 임시 DB에서만 수행했다.
- 실제 API Android 시나리오 1개가 통과했다. 임시 계정·후기는 합성 SAMPLE 데이터이며 외부에서 수집한 실측 통계가 아니다. live-admin 이미지 2개는 이 격리 환경이다.
- 임시 서버·DB 프로세스와 비공개 작업 폴더를 정리했다. 기존 8080·18080 서버는 동일한 프로세스로 유지했다. [격리 검증 결과](live-result.json), [Android 실행 기록](live-android-run.txt).
- 일반 진입점 lib/main.dart로 APK를 빌드·설치해 로그인 전 화면 진입, 핫 리로드 성공, Dart 실행 오류 0건을 확인했다. APK의 새 관리 화면 포함과 테스트 진입점·검증 계정 설정 제외도 확인했다.

## 모의·자동 검증

- 전체 단위·화면 테스트 **88개 통과**, 정적 검사 오류·경고·정보 0건. [테스트](test-run.txt), [정적 검사](analyze-run.txt), [빌드](build-run.txt).
- Android MockClient 시나리오 2개 통과. 앱 내부 진입·수집 입력·시작/취소·후기 페이지/상세·출처 추가·초기화 확인 취소·연결 오류 재시도·일반 회원 메뉴 숨김을 확인했다. admin- 이미지 10개는 모두 SAMPLE이다.
- 320·360·412 너비와 150·200% 글자에서 관리 홈·수집·출처·조회 조건 이동과 넘침을 확인했다. 실제 OS 키보드 전체 조합이나 TalkBack 낭독을 검증한 것은 아니다.
- 확인창을 닫을 때 입력 컨트롤러가 먼저 해제되는 문제를 재현하고 확인창이 직접 수명을 관리하도록 수정했다. 권한 거부 후 현재·이전 화면에 조회 정보가 남던 문제와 상세 화면 뒤에서 앱 복귀 시 상태를 조회하던 문제도 실패로 재현한 뒤 회귀 검사를 통과했다.
- 403은 전체 관리 화면·상세의 캐시를 즉시 숨기고 추가 요청을 막으며 일반 로그인은 유지한다. 401은 기존 세션 만료 처리를 사용한다. 로그아웃·권한 거부 후 늦게 도착한 응답을 반환하지 않는다. 리다이렉트를 따르지 않고 토큰은 같은 서버의 정해진 관리자 API에만 보낸다.
- 실행 중 작업의 상태 조회는 전경·현재 화면에서만 3초 간격으로 수행한다. 화면 종료·앱 배경에서는 조회를 멈춘다. 외부 검토에서 나온 중요 사항 2개와 검색어 길이 제한을 보완했고 재검토에서 남은 중요 문제는 없었다.

## 백엔드 보존

작업 전후 팀 프로젝트 비교 대상 **202개**, 기존 테스트 백엔드 **66개**에 추가·삭제·내용 변경이 없다. 앱의 기존 생산 파일 49개 중 admin_link.dart만 변경했고 admin_ 화면 파일 7개를 추가했다. 다른 기존 UI·데이터 모델·세션·보안 저장소·패키지·설정·SQL·다른 팀원의 TODO 코드는 변경하지 않았다. 팀 Git 변경도 0건이다. 생성 파일·로그·.git·.idea·build·.gradle·.runtime 등 제외 범위는 비교 JSON에 명시했다.

## 갱신

## 참고 기준·미검증

기존 [API 컨트롤러](C:/Users/std66/passpace11144/src/main/java/com/passpace/controller/CollectAdminController.java)·웹 관리자 요청 규격과 DTO를 직접 읽어 사용했다. 화면은 기존 [디자인 기준](../ui-refresh/report.md)과 변경하지 않은 lib/ui/design.dart를 따랐다. 캡처는 설치된 Flutter SDK의 integration_test_driver_extended를 사용했다.

개인 휴대폰 설치, 사용자의 기존 계정 로그인, 실제 외부 사이트의 수집·중단·후기 추출, 외부 API 키가 있는 네이버 수집, 실제 TalkBack·모든 OS 키보드 조합은 미검증이다. 크롤링·네이버의 시작/중단 요청과 상태 표시는 모의 검증했으며 실제 외부 수집 성공을 주장하지 않는다. 이번 관리자 화면 전환에 필요한 백엔드 변경이나 별도 보류 사항은 없다. 기존 React 웹·루트 백엔드의 Build/Postman 검사는 실행하지 않았으며 변경 대상인 앱과 기존 팀 API의 격리 시나리오로 검증했다.
