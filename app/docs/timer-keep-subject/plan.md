# 저장 후 과목 유지 Implementation Plan

> 현재 세션에서 superpowers:executing-plans로 구현하고 읽기 전용 최종 검토1회. 커밋/배포 없음.

**Goal:** 저장 후 같은 타이머 화면에서 시계0·선택 과목·저장 누적 원을 유지하고 바로 새 측정을 시작한다.
**Architecture:** 기존 timer.complete/reset은 그대로 두고 성공적으로 초기화된 같은 계정/같은 타이머에 기존 choose()로 선택만 복원한다. 저장 성공은 목록 강제 이동을 없애고, 알림으로 연 타이머도 입력 화면 위에 유지한다. 확정된 저장의 기기 정리 재시도/명시적 저장 확인도 같은 선택 복원을 사용한다. 수동 초기화는 기존대로 선택을 지운다.
**Constraints:** 백엔드·API·DB·인증/모델/측정/알림·키/패키지/환경 버전 변경 없음. lib/ui/study_timer_screen.dart, study_records.dart, study_timer_progress.dart와 관련 검사/문서만 수정. 사용자 변경은 scope-before.json/git-before.txt 기준 보존.

- [x] 저장 후 화면/선택 유지와 빠른 시계 초기화 후 누적 재조회 RED.
- [x] 확인된 저장 후만 선택 복원. 같은 소유자·유효한 idle0 타이머·빈 선택에만 적용. 계정 변경/폐기된 타이머/새 선택을 덮지 않음.
- [x] 저장→새 측정·과목의 기기 복원·화면 이동 중 저장·기기 저장 실패 재시도·결과 확인·수동 초기화·입력 위 알림 타이머 회귀.
- [x] 전체 Flutter/정적 검사·독립 최종 검토1회·필요 수정.
- [x] Android의 모의 저장15분→과목 재선택 없이5분 측정/재저장20분 검증·화면. 실 API 쓰기 없음.
- [x] 일반 APK 빌드/업데이트·핫 리로드/런타임·백엔드/앱 비대상 해시 비교·검증 문서.

Ruling: 자동으로 새 측정을 시작하지 않는다. 저장 후 사용자가 같은 화면의 측정 시작을 누른다. 계획이 교체된 경우 기존 배정/연결 검증과 재선택 안내를 유지한다. 결과 불명확 시 기존 확인 절차 전까지 새 측정을 허용하지 않는다.
