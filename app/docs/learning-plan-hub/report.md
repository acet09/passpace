# 목표·계획 통합 결과

2026-11-15. 목표 설정과 저장된 계획을 하단 **학습계획** 한곳으로 모았다. 홈의 목표·설정과 내 정보의 학습계획 관리도 이곳으로 연결한다.

**사용 흐름:** 학습계획 → 설정 수정 → 목표 저장 → 이 설정으로 계획 만들기 → 미리보기·비교 → 확인 후 저장.

설정만 저장하고 나중에 계획을 작성해도 된다. 기존 시간과 과목 ID가 일치하는 이해도는 기존 불러오기 기능을 사용한다. 시험 종류를 특정할 수 없는 기본 목표일은 기존처럼 사용자가 시험별로 확인해 적용한다. 목표 저장이 기존 일정 변경을 의미하지 않으며, 계획 저장은 기존 확인 절차를 거친다.

## 실제 검증

- Android 에뮬레이터에서 기존 팀 Spring Boot 코드와 별도 MariaDB를 사용하는 통합 시나리오 1개가 통과했다. 사용자 계정과 기존 팀 DB에는 검증 데이터를 쓰지 않았다.
- 설정 125분 저장·재조회, 통합 화면 복귀, 저장된 설정으로 계획 작성, 보안 저장소의 초안 복원, 서버 미리보기, 변경 상세, 저장 취소와 명시적 저장, 교체 버전 및 다른 로그인에서의 조회를 확인했다. 가입·로그인·상담·회원정보 수정도 기존 시나리오에서 확인했다.
- 실제 API 화면 16개를 캡처했고 통합 화면의 저장 완료·일정·내 정보 배치를 확인했다. 이미지의 계정과 학습 데이터는 격리된 검증 환경의 값이다. 상담은 외부 LLM 없이 기존 Java 기본 안내를 사용했다.
- 일반 진입점 lib/main.dart로 디버그 APK를 빌드·설치했다. 새 통합 화면 문구가 포함되고 통합 테스트 진입점은 포함되지 않는 것을 확인했다. 위젯 검사에서 일반 로그인 화면 진입을 확인했고 핫 리로드가 성공했다. Dart 런타임 오류는 0건이다.
- 실행 로그의 기존 Android 보안 저장소 키 읽기 경고는 남아 있다. 로그인 화면은 정상 진입했고 보안 저장소 초안·로그인 복원은 위 실제 API 시나리오에서 통과했다. 데이터 계층은 변경하지 않았다.
- 검증용 서버·임시 DB·폴더를 정리했다. 기존 팀 8080 서버는 인증 없는 회원 조회에 401로 응답했다.

## 모의·자동 검증

- 전체 단위·화면 테스트 39개 통과. Flutter 정적 검사에서 오류·경고가 없었다.
- 새 허브 테스트 7개는 HTTP 응답을 대체한다. 설정만 저장하면 계획 저장 요청이 발생하지 않으며, 시간·이해도가 기존 방식으로 입력에 반영되는 것을 확인했다. 취소는 쓰기 요청 없이 돌아가고 저장 실패는 입력과 기존 일정을 유지한다.
- 애니메이션 제거 설정에서 아래로 스크롤한 후 다시 학습계획을 누르면 발생하던 오류를 실패로 재현한 뒤 수정·통과했다. 지연 응답 중 목록이 로딩 화면으로 교체되던 상황도 재현했고, 응답 전후 기존 목록과 스크롤 위치가 유지되도록 수정·통과했다.
- 기존 320·360·412 너비와 150·200% 글자 검사, 초안·기존 값·미리보기·비교·명시적 저장 검사가 통과했다. 이 결과는 실제 TalkBack 낭독이나 모든 OS 조합을 검증했다는 뜻은 아니다.

## 수정 범위 검증

- 팀 프로젝트 소스·설정 203개와 앱 보호 파일 55개의 작업 전후 SHA-256 비교에서 추가·삭제·변경이 모두 0건이다. 팀 프로젝트 Git 상태도 변경이 없었다.
- 앱 보호 범위에는 API·모델·세션·보안 저장소·의존성·플랫폼·실행 설정이 포함된다. 목표 저장·검증 메서드와 계획 작성 파일도 그대로다.
- Java·Spring Boot·DB·SQL·웹 프론트엔드·팀 설정·실행 스크립트와 다른 팀원 담당 코드는 수정하지 않았다. 제거된 기학습·산정 근거·계산 기준 UI도 복구하지 않았다.

## 보류 사항

목표 저장과 계획 승인을 서버의 한 번의 저장으로 합치는 동작, 설정 변경 즉시 기존 일정 자동 재계산, 원자적 버전 충돌 처리는 기존 API 변경이 필요하므로 구현하지 않았다. 기존 화면의 미리보기·확인·취소·저장으로 이어진다. 개인 휴대폰·인터넷·스토어 배포와 외부 LLM은 미검증이다.
