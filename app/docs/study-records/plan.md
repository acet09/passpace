# 학습기록과 개인 시간통계 앱 연결 계획

사용자가 승인한 앱 변경만 수행한다. `C:/Users/std66/passpace11144`와 기존 테스트 백엔드는 읽기 전용이며 Java·SQL·설정·버전·기존 실행 스크립트는 변경하지 않는다. 앱의 기존 로그인·회원가입·목표·계획·상담·관리자 기능을 유지한다. 기존 패키지만 사용한다.

## 구현 방향

- 하단 ‘기록’ 탭에서 기록 목록과 개인 통계를 전환한다. 기존 오늘·학습계획·상담·내 정보 이동을 유지한다.
- 새 API에 맞춘 타입을 `lib/data/study_models.dart`에 추가하고 `lib/data/api.dart`에 세 요청을 연결한다. 기존 인증·세션·보안 저장소는 재사용한다.
- 새 화면은 `lib/ui/study_records.dart`, 입력은 `study_record_form.dart`, 통계 그래프는 `study_chart.dart`로 나눈다. `dashboard.dart`에는 탭 연결만 추가한다.
- 기존 계획 조회에는 taskId가 없어 날짜와 실제 정수 분을 입력하는 미연결 수동 기록을 저장한다. 과목·계획 ID를 추측하지 않는다. 서버가 반환한 연결 정보는 목록에 표시한다.
- 기간은 최근 7일·30일 또는 최대 366일의 직접 선택이며, 통계와 목록은 동일한 날짜 범위를 사용한다. API의 실제 합계·일별 분만 표시한다. 완료율·합격 가능성·연속 학습·가짜 타이머는 추가하지 않는다.
- 꺾은선·막대 보기와 일별 숫자 확인을 제공한다. 월은 위쪽 범위로, 일은 겹치지 않도록 간격을 두고 표기한다.
- POST는 자동 재전송하지 않는다. 통신·응답 해석 실패로 저장 여부가 불확실하면 입력을 유지하고 목록 확인을 먼저 안내한다. 서버가 명확히 거부한 4xx에서는 입력을 유지해 수정할 수 있게 한다.
- 계정·서버·기간·화면 활성 상태가 바뀌면 늦게 도착한 응답을 폐기한다. 401/403 뒤 개인 기록과 통계를 숨기며, 입력·응답을 로그에 남기지 않는다.

## 검증 순서

1. 작업 전 팀·기존 백엔드·앱 해시와 기존 Flutter 테스트를 기록한다.
2. MockClient·메모리 세션으로 기록 탭 진입 검사를 먼저 작성해 누락된 기능 때문에 실패하는 것을 확인한다.
3. API/모델, 기록·입력·그래프, 탭 연결을 구현하고 계약·오류·페이지·경합·입력 보존 검사를 수행한다.
4. 320·360·412 너비, 글자 150~200%, 키보드·취소·저장 실패·빈 목록·연결 오류·권한 변경을 확인한다.
5. 실제 API에 쓰는 검사는 별도 DB·서버·합성 계정에서만 실행한다. 기존 계정에는 기록을 만들지 않는다.
6. 전체 Flutter 검사와 정적 분석, Android 실행·화면 확인, 핫 리로드/재시작, 일반 진입점 APK 생성·검증을 수행한다.
7. 전체 변경을 독립 읽기 전용 검토하고 중요 문제를 재현 후 수정한다. 최종 백엔드 해시 비교, 변경 파일·실제/모의/미검증·APK 경로를 검증 문서에 기록한다.

## 검토 초점

- 불확실한 저장 결과와 이중 탭이 중복 POST를 만들지 않는가.
- 로그아웃·계정/토큰 변경·403 뒤 이전 응답이 개인 데이터를 다시 보여주지 않는가.
- 기간 변경·페이지 추가·저장 후 복귀가 오래된 범위나 잘못된 목록을 표시하지 않는가.
- 계획 시간을 실공부시간으로 사용하거나, 서버에 없는 과목 ID·진도·합계를 만들지 않는가.
- 큰 글자·좁은 너비·키보드에서 입력과 주요 조작이 가려지지 않는가.
