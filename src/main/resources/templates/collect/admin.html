velog 와 티스토리의 수집 방법이 다른 이유

velog — 검색어로 찾습니다. velog 의 태그·검색 결과 화면은 서버가 글 목록을 화면 안에 담아 보내 주므로, 수집기가 그 화면만 읽어도 글 주소를 뽑을 수 있습니다. 그래서 검색어(검색 화면 주소)를 등록해 두면 수집할 때마다 그 검색어의 최근 글 약 20개를 자동으로 찾습니다. 더 오래된 글은 화면을 내릴 때 velog 내부 API 로 불러오는 방식이라 쓰지 않으므로, 범위를 넓히려면 검색어 수를 늘립니다.

티스토리 — 검색어(브라우저), 글 주소, 블로그 RSS 로 찾습니다. 티스토리 통합 검색 결과는 브라우저에서 스크립트가 실행된 뒤에야 그려져서, 글자만 받아 오는 일반 요청으로는 결과가 비어 있습니다. 그 데이터를 주는 내부 API 를 직접 부르는 것은 서비스 모방·우회에 해당할 수 있어 쓰지 않고, 대신 PC 에 설치된 크롬을 화면 없이 실행해 사람이 보는 것과 같은 방식으로 공개 검색 화면만 읽어 글 주소를 찾습니다 (www.tistory.com 에는 robots.txt 가 없어 제한 없음, 카카오 통합약관 제12조 검토 완료, 화면 사이 5초 간격, 우리 봇 이름 표시). 글 본문은 지금처럼 각 블로그의 robots.txt 를 지키며 가져옵니다. 직접 등록한 글 주소와 블로그 RSS(/rss)도 함께 씁니다.

참고: 통계는 같은 작성자를 1건으로 세므로, 같은 블로그에서 글을 더 찾으면 수집 건수는 늘지만 통계 표본은 크게 늘지 않습니다. 새 작성자를 늘리는 데는 velog 검색어 추가와 새 티스토리 글 주소 등록이 효과적입니다.

검색어 1개를 등록하면 수집할 때마다 그 검색 결과의 최근 글 약 20개를 찾습니다. 태그 주소(https://velog.io/tags/…)도 넣을 수 있습니다.

    검색어를 등록하면 수집할 때 티스토리 통합 검색 화면을 읽어 새 블로그의 후기 글을 찾습니다(PC 에 크롬 필요, 검색어당 최대 5쪽, 6시간에 한 번). 글 주소를 등록하면 그 글 하나를, 블로그 RSS 주소(https://블로그.tistory.com/rss)를 넣으면 그 블로그의 후기 글을 찾습니다.

      후기 수집

      velog 검색어 · 티스토리 글 주소 · 수집 이력
      수집 방식과 정책
      velog 는 수집 범위의 태그·검색 화면에서 후기 글을 찾고(1단계만), 티스토리는 등록된 글 주소와 (켜면) 블로그 RSS 를, 그리고 수집 이력 파일에서 저장했던 글을 후보로 씁니다. DATA_SOURCES 의 허용 확인 날짜(permission_checked_at)가 없는 사이트는 건너뜁니다. 요청 간격은 velog 1.5초·티스토리 0.5초이고 robots.txt 의 Crawl-delay 가 더 크면 그 값을 따릅니다. 403·429 는 즉시 멈추고, 목록에 적힌 작성일이 3년 지난 글은 요청하지 않습니다. 원문과 작성자 아이디는 저장하지 않습니다.

      복구

      크롤링 후기가 지워졌을 때

      수집기는 찾은 글 주소와 판정 결과를 수집 이력 파일(프로젝트 폴더, 본문 없음)에 계속 기록합니다. 후기가 지워져도 이 파일로 한 번이라도 저장했던 글을 목록 탐색 없이 바로 다시 수집하고, 초기화 직전 기록과 비교해 복구율과 값 일치율을 보여 줍니다.

      초기화 → 복구 수집을 실행하면 결과가 여기에 표시됩니다.

      크롤링 후기 초기화

      되돌릴 수 없음

      velog·티스토리에서 수집한 후기를 VALID 포함 모두 지웁니다. 더미 후기·시험일정·회원 데이터와 수집 이력 파일은 지우지 않습니다. 지우기 직전 상태를 기록하므로 복구 후 복구율을 비교할 수 있습니다. 수집 중에는 실행되지 않습니다.
