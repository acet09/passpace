# 앱 내부 관리자 화면 · 2026-11-15

목표: 내 정보의 관리자 메뉴에서 Flutter 관리 화면으로 이동하고 기존 ADMIN JWT로 기존 수집 API를 사용한다. 외부 브라우저 실행과 별도 웹 로그인은 이 동선에서 제거한다.

수정 범위: lib/ui/admin_link.dart와 새 lib/ui/admin_*.dart, 관련 test·integration_test, 앱 검증 문서. lib/data, main.dart, Android 네이티브 코드, 의존성·환경·팀 프로젝트·루트 백엔드는 유지한다. 기존 표시용 관리자 판정은 그대로 옮겨 재사용하고 실제 권한은 서버가 검증한다.

접근 방식: 기존 API를 사용하는 Flutter 화면을 구현한다. WebView는 새 의존성과 별도 웹 인증 처리가 필요하고, 외부 브라우저는 이번 요청에 맞지 않아 선택하지 않는다. 기존 HTTP 클라이언트·서버 주소·토큰·만료 콜백을 재사용하는 UI 전용 관리자 어댑터에서 관리자 경로만 호출한다. 기존 데이터·인증 계층의 요청이나 저장 로직은 바꾸지 않는다.

- [x] 기존 메뉴 탭이 브라우저를 실행하는 실패를 새 화면 테스트로 재현한다.
- [x] 관리자 어댑터: 기존 응답 봉투, form-urlencoded 요청, UTF-8·타임아웃·401/403·리다이렉트 거부·로그인 교체를 처리한다. 목록과 단순 숫자 응답도 지원한다.
- [x] 관리 홈, 후기 수집·중단·진행 조회, 시험일정 수집·참고시간 집계, 출처 추가·삭제·검사·후기 미리보기, 필터·정렬·페이지 조회, 복구·초기화 화면을 구현한다. 자동 저장·자동 수집은 하지 않는다.
- [x] 수집 조회는 활성 화면·앱 전경·실행 중 작업에 한해 3초 간격으로 요청하고, 중복 요청·화면 종료 후 갱신을 막는다. 실패는 재시도 동선과 함께 표시한다.
- [x] 초기화는 서버의 삭제 예정 건수를 조회한 뒤 정확한 확인 문구를 입력해야 실행한다. 취소 시 POST가 없어야 한다. 출처 삭제·수집 실행도 명시적 확인을 받는다.
- [x] 기존 테스트·정적 검사와 새 화면/요청 계약 테스트를 실행한다. 320·360·412 너비 및 150·200% 글자를 확인한다.
- [x] 에뮬레이터 모의 시나리오와 실제 API의 읽기/권한 검증을 구분해 기록한다. 실제 API 쓰기는 격리된 환경에서만 검증한다.
- [x] 일반 진입점 APK를 갱신·설치하고 핫 리로드·런타임 오류를 확인한다. 팀·백엔드·앱 보호 파일의 작업 전후 해시를 비교한다.

검토 초점: 만료·권한 거부 뒤 요청 차단, 토큰의 외부 전달 방지, 화면을 나간 동안의 폴링, 필터 실패 시 이전 결과 오인 방지, 취소·중복 탭·틀린 확인 문구에서 삭제 요청이 없는지.
