# 학습기록 수정 구현 계획

사용자 승인: 기존 `com.passpace.study` Java 6파일과 Flutter 앱만 변경한다. 다른 팀원 코드·웹·DB 구조·보안·환경·의존성·기존 실행 스크립트는 보존한다. 기존 저장·조회·통계 API 목록을 문서로 남긴다. 구현은 현재 세션에서 수행한다.

## 계약과 설계

- `PATCH /study/sessions/{sessionId}`를 추가한다. 날짜/분 두 값은 한 번에 수정한다. 본문은 `studyDate`, `durationMinutes`, `expectedStudyDate`, `expectedDurationMinutes` 네 필드가 필수다. 알 수 없는 필드는 거부한다.
- 기존에 읽은 날짜/분을 현재 DB 값과 비교하고 다르면409를 반환한다. 별도 version 컬럼이 없는 기존 스키마를 유지하기 위한 값 비교 방식이며, 단조 증가 revision 이력이나 A→B→A 전체 변경 감지를 보장한다고 표현하지 않는다.
- JWT/전공/본인 소유권 확인과 사용자 행 잠금 뒤 기록을 잠근다. 기존 직접 입력(MANUAL) 기록을 정정하며 ID/과목/계획/입력 방식/시작·종료 시각/이해도는 바꾸지 않는다.
- 목표 날짜는 한국 기준 오늘 이하, 정수1~1440분. 이동하는 날짜의 합계는 기존 값 중 같은 기록의 분을 제외한 뒤 검사한다. 초과/경합/오래된 값은409, 잘못된 요청400, 본인 소유 아님403, 기존 불량 연결/시간503이다. 기존 성공200/envelope/SessionResponse를 재사용한다.
- 앱의 직접 입력 기록에 ‘수정’을 제공한다. 기존 입력 폼에 날짜와 분을 채워 수정 모드로 연다. 취소/실패에서는 값 보존, 성공하면 목록과 서버 통계를 재조회한다. 조회 범위 밖 날짜로 이동하면 수정된 날짜를 보여준다.
- PATCH는 자동 재전송하지 않는다. 응답 유실 시 목록에서 확인하고,409에서는 목록을 다시 확인하도록 안내한다. 인증/권한/늦은 응답/중복 탭 보호를 유지한다.

## 수정 파일

- 팀: `src/main/java/com/passpace/study/{StudyController,StudyService,StudyServiceImpl,StudyRepository,JdbcStudyRepository,StudyDtos}.java`만.
- 앱: `lib/data/api.dart`, `lib/ui/study_record_form.dart`, `lib/ui/study_records.dart`; 관련 테스트·격리 검증 도구·문서만.
- 실제 팀 테스트/공통 코드에는 새 파일을 추가하지 않는다. Java 회귀 검사는 앱의 검증 자료로 보관하고 별도 프로젝트 복사본에 주입해 실행한다.
- 계약과 생성기는 앱의 `docs/api-contract.md`, `scripts/generate-api-artifacts.py`에 둔다. 루트의 기존 React/쿠키 인증 API 문서와 생성기는 다른 서비스 계약이므로 수정하지 않는다.

## 검토 초점

1. 동일 날짜 수정에서 자기 기록을 중복 집계하지 않는가.
2. 날짜 이동 후 이전 날짜/대상 날짜 통계와 목록을 서버 값으로 다시 조회하는가.
3. 다른 사용자·과목·계획·타이머·완료 이력을 수정하지 않는가.
4. 다른 기기에서 먼저 수정하거나 통신이 끊겼을 때 자동 재시도로 덮어쓰지 않는가.
5. 입력 중 인증 변경/큰 글자/키보드/이중 탭과 기존 저장 흐름이 유지되는가.

Ruling: 기존 사용자 승인으로 PATCH 추가와 앱 연결 방식이 확정되어 추가 승인 질문 없이 진행한다. 새 DB 컬럼/마이그레이션 대신 기존 날짜·분 비교와 사용자/기록 행 잠금으로 현재 값의 덮어쓰기를 막는다. 다른 팀원의 DB 정책·보안 구현은 변경하지 않는다.
