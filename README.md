# PASS PACE Android

팀 백엔드 브랜치 `feature/passpace-backend-hangyeol`의 Spring Boot API를 사용하는 Flutter/Dart 안드로이드 앱입니다. 웹과 같은 서버에 로그인하면 같은 회원 정보, 학습 목표, 저장된 계획을 읽고 수정합니다. 이 폴더만 Android Studio에서 열 수 있습니다.

## Android Studio에서 실행

1. IntelliJ에서 백엔드 브랜치의 README에 따라 Spring Boot를 실행합니다. 기본 포트는 `8082`입니다. `서버 켜기.cmd`를 사용하는 경우 앱 폴더 옆에 백엔드를 `backend` 폴더로 두거나 `PASSPACE_SERVER_DIR`에 백엔드 경로를 지정하세요.
2. Android Studio에서 **File → Open**으로 앱 저장소의 루트 폴더를 엽니다. 이 폴더에 `pubspec.yaml`이 있습니다. Flutter 및 Dart 플러그인이 필요합니다.
3. Pixel 에뮬레이터를 선택하고 **main.dart → ▶ Run**을 누릅니다. 앱의 기본 개발 서버는 `http://10.0.2.2:8082`입니다. 기존 설치에 8080 주소가 저장돼 있다면 **서버 연결 설정 → 에뮬레이터 → 연결 주소 저장**을 한 번 선택하세요.
4. 로그인 화면에서 웹 계정의 **아이디**와 비밀번호를 입력합니다.

## 개인 휴대폰에서 사용

- **USB 개발** 휴대폰에서 USB 디버깅을 허용한 뒤 PC에서 `adb -d reverse tcp:8082 tcp:8082`를 실행합니다. `서버 켜기.cmd`는 연결된 USB 휴대폰 한 대에 이 설정을 적용합니다. 앱의 **서버 연결 설정 → USB 연결 → 연결 주소 저장**을 선택하면 `http://127.0.0.1:8082`로 연결됩니다. 케이블 재연결 후에는 포트 연결을 다시 적용하세요.
- **케이블 없이 사용** 휴대폰에서 접근 가능한 HTTPS 팀 서버를 준비하고 로그인 화면의 연결 설정에 그 주소를 저장합니다. 서버 연결이 필요한 기능은 서버와 DB가 실행 중일 때 사용할 수 있습니다.
- **APK 만들기** 이 폴더에서 `flutter build apk --debug`를 실행합니다. 결과 파일은 `build/app/outputs/flutter-apk/app-debug.apk`입니다. 배포용 기본 서버는 빌드 시 `--dart-define=PASS_PACE_API_URL=https://서비스주소`로 지정합니다. 스토어 배포 시 팀의 정식 서명 설정이 필요합니다.

## 계획 초안과 기존 값

작성한 시간·요일·시험·이해도·단계를 기기에 자동 저장합니다. 계정과 서버 주소별로 초안이 분리됩니다. 계획 만들기를 다시 열어 **이어서 작성**을 누르면 저장된 단계에서 계속할 수 있고, **새로 작성**은 해당 초안을 정리합니다. 휴대폰 뒤로가기는 이전 단계로 이동하며 첫 단계에서 나갈 때 초안을 저장합니다.

계획 입력에서는 과목 이해도만 선택합니다. 진도·누적 학습 입력과 학습량 근거·계산 기준 상세 안내를 제거했으며, 이전 버전 초안의 진도·누적 학습 값도 새 요청에는 반영하지 않습니다. 하루 시간은 기존 서버에서 사용하는 의미에 맞게 **하루 최대 학습 시간**으로 표시합니다.

저장한 기본 목표의 시간과 과목 ID가 일치하는 이해도를 먼저 채웁니다. **기존 값 불러오기**로 다시 적용할 수 있습니다. 기본 목표일은 선택한 시험에 맞는지 확인한 뒤 **저장한 목표일 사용**으로 적용합니다. 초안 저장은 활성 계획 승인과 별도로 처리하며, 계획 저장에 성공하면 해당 초안을 정리합니다.

기존 계획이 있으면 미리보기에서 현재·새 배정 시간과 추가·제외·시간 변경을 비교할 수 있습니다. **변경 상세**는 날짜·시험·과목별 시간을 보여줍니다. 저장 직전 현재 계획을 다시 조회하며, 확인하는 동안 다른 계획이 저장됐다면 비교 내용을 갱신해 재확인을 안내합니다.

## 학습기록 관리와 추가 API 목록

기록 목록의 **수정**에서 직접 입력한 기록의 날짜·공부시간·연결 과목을 바꿀 수 있습니다. **삭제**는 확인창에서 확정하며, 취소하면 기록을 유지합니다. 저장·삭제 후 목록과 개인 통계를 서버에서 다시 조회합니다.

추가·수정 화면의 **과목 연결 · 선택**에서 현재 학습계획의 과목을 고릅니다. 날짜별로 반복되는 같은 과목은 한 번만 표시하며 다른 자격증의 과목은 구분합니다. **이전 계획 포함** 옵션은 제거했습니다. 과목 연결은 선택 사항이며 입력한 공부시간을 계획 시간으로 덮어쓰지 않습니다. 과거에 저장한 기록의 연결은 자동으로 변경하지 않습니다.

**기록**을 누르면 집중 타이머가 바로 열립니다. 시작·일시정지·계속 측정 후 **기록 저장**을 누릅니다. 측정한 정수 분을 기존 학습기록 API로 저장하며, 이후 날짜·시간 수정과 삭제가 가능합니다.1분 미만은 저장하지 않고 남은 초는 화면에서 안내합니다. 앱을 이동해도 측정하며, 날짜가 바뀌면 그날의 측정을 멈춥니다. 기기에 서버·계정별 상태를 보관해 다시 열 때 복원합니다.

선택 과목의 해당 날짜 배정 시간을 큰 원으로 표시합니다. **그날 같은 과목으로 저장된 시간 + 이번 미저장 측정**을 합산해 원을 채웁니다. 예를 들어 배정30분에 저장15분·이번5분이면 누적20분을 표시합니다. 저장 후에는 같은 타이머 화면에서 선택 과목과 저장된 누적 시간을 유지하고, 이번 시계만0으로 돌아갑니다. **측정 시작**을 누르면 과목을 다시 고르지 않고 이어서 측정합니다. 자동으로 측정을 시작하지 않으며, 직접 **측정 초기화**하면 과목 선택도 초기화됩니다. 중앙 시계는 이번 측정이며 저장할 시간도 이번 측정분만 사용합니다. 배정 시간에 도달해도 측정은 계속되고, 배정이 없거나 조회에 실패하면 임의의 목표나 부분 합계를 표시하지 않습니다.

측정 중에는 Android 알림창에서 과목과 경과 시간을 확인할 수 있습니다. 처음 요청하는 알림 권한을 허용하세요. 거부해도 앱의 측정은 계속되며 안내의 **알림 설정**에서 변경할 수 있습니다. 알림을 누르면 타이머로 돌아옵니다. 입력 화면을 열어둔 경우 입력을 보존한 채 타이머를 그 위에 표시합니다. 일시정지·저장·초기화·로그아웃하면 진행 알림을 종료합니다.

저장 결과가 불확실하면 자동 재전송하지 않습니다. 기록 목록을 확인한 뒤 **저장된 기록 확인**으로 측정을 마치거나 **기록 없음 · 측정 유지**로 측정값을 보관합니다. 다시 저장할 때는 중복 기록이 없는지 먼저 확인합니다.

**개인 통계**는 기존 기간·꺾은선/막대 그래프를 유지하며 날짜·요일·시간/분으로 일별 공부시간을 보여줍니다. 긴 기간도7일씩 이동해 확인할 수 있습니다. 데이터의 날짜 기준과 API 계약은 그대로이며 화면의 시간대 기술 문구만 제거했습니다.

[타이머·과목·통계 개선 검증과 화면](docs/study-timer/verification.md). 이 개선은 앱만 변경했으며 서버 API·DB·다른 팀원 코드·패키지 버전은 유지했습니다.

[기록 탭 분리·진행 알림·월간 달력의 전후 화면과 검증](docs/timer-navigation/verification.md). 새 일반 APK를 에뮬레이터에 업데이트했습니다. 실제 휴대폰은 같은 APK로 업데이트한 뒤 알림 권한을 허용하세요. 물리 휴대폰의 잠금·절전 상태는 별도 확인이 필요합니다.

[주간·월간 및 타이머·통계 선택 바 개선](docs/ui-switches/verification.md). 홈에서도 **주간·월간**을 함께 표시해 현재 선택을 구별합니다. 이후 요청으로 과목 연결은 현재 계획의 과목만 제공하도록 정리했습니다.

[과목별 배정 시간 원형 타이머·현재 계획 과목 검증](docs/timer-ring/verification.md). 백엔드·API·DB·시간 측정·알림·기록 저장 방식은 그대로 유지했습니다.

## 2026-11-19 변경 사항 (학습계획·상담)

서버(`passpacehg`, 브랜치 `feature/passpace-chat-donggeon`)와 앱을 함께 바꿨습니다. 새 기능을 쓰려면 Spring Boot 서버를 재시작하고 앱을 다시 실행합니다. 새 테이블은 만들지 않았습니다.

### 저장한 계획을 여러 개 관리
- 계획을 저장해도 이전 계획이 사라지지 않고 목록에 쌓입니다. 그중 하나만 **사용 중**이고 나머지는 **보관**입니다. 홈·달력·타이머는 사용 중인 계획을 따릅니다.
- 저장할 때 **바로 사용 / 목록에만 추가 / 취소** 중에서 고릅니다 (상담 카드, 학습계획 만들기 공통).
- **학습계획** 탭 오른쪽 위 목록 아이콘 → **저장한 계획** 화면에서 `이 계획 사용`, `일정 보기`, `삭제`를 합니다.
- 학습기록이 연결된 계획은 기록이 끊기지 않도록 삭제를 막습니다.

### 상담에서 요일과 요일별 시간 말하기
- "월수금만 가능해", "주말은 안 돼", "화요일이랑 목요일 빼고", "월~금"처럼 되는 요일·안 되는 요일을 말하면 계획 카드의 공부 요일에 먼저 넣습니다.
- "평일엔 2시간, 주말엔 4시간", "월수금 1시간씩 토요일은 3시간 반"처럼 요일마다 다른 시간을 말하면 **요일별 공부시간**으로 넣습니다.
- 계획 카드를 연 뒤에 요일이나 요일별 시간만 다시 말해도 열려 있는 카드에 반영하고 안내를 보여 줍니다. 계산은 카드에서 다시 누릅니다.
- "화요일은 알바가 있어"처럼 되는지 안 되는지를 직접 말하지 않은 문장은 읽지 않습니다.

### 계획 카드: 한 번에 하나씩 묻기
- 긴 입력 폼 대신 **시간 → 요일 → 기간 → 자격증별 이해도** 순서로 질문 하나만 보여 줍니다. 답하면 한 줄로 접히고 다음 질문이 열립니다.
- 시간 버튼, `매일/월~금/토·일` 버튼, 마지막 과목의 이해도를 누르면 `다음` 없이 넘어갑니다.
- 질문에서 이미 읽은 값은 **질문에서 읽음**으로 접어 두고 다시 묻지 않습니다. 접힌 줄을 누르면 고칠 수 있습니다.
- 시간 질문의 **요일마다 시간 다르게**를 켜면 월~일 각각 시간을 고릅니다. `쉬는 날`인 요일에는 배정하지 않습니다. 이때 요일 질문은 생략되며, `자격증별로 시간 나누기`와 함께 쓸 수 없습니다.

### 계획이 밀리면 재편성 추천
- 어제까지 배정된 시간 중 하지 못한 시간이 **계획 전체의 20% 이상**이면 홈에 추천 카드가 뜹니다 (100일치 계획이면 20일치를 못 했을 때).
- `다시 짠 일정 보기`에서 남은 공부량을 오늘부터 원래 끝나던 날까지 다시 나눈 일정을 확인하고, `이 일정으로 바꾸기`를 누르면 새 계획이 사용 중이 되고 쓰던 계획은 보관됩니다.
- `나중에`를 누르면 7일 동안 다시 묻지 않습니다.
- 밀림 판단은 계획 시작 후의 모든 학습기록을 세고, 과목별 남은 양은 할 일에 연결해 기록한 시간만 뺍니다.
- 서버가 정해진 시각에 확인하지 않고, 홈을 열거나 새로고침할 때 확인합니다.

### 그 밖의 변경
- 최소 학습 블록을 45분에서 **50분**으로 바꿨습니다.
- 관리 화면 **시험일정 → 후기 기반 참고시간**에 `과목 언급 채우기` 버튼을 추가했습니다 (이미 저장한 velog·티스토리 후기 30건의 본문을 다시 읽어 과목 언급만 저장).

### 이번에 추가·변경한 API (`/api/chat/planner/review-based`)

| 메서드 | 경로 | 내용 |
|---|---|---|
| POST | `/save?activate=false` | `activate` 추가. 기본값 true(바로 사용), false면 목록에만 추가 |
| GET | `/plans` | 저장한 계획 목록 (사용 중인 계획이 맨 위) |
| GET | `/plans/{planId}` | 계획 한 건의 날짜별 할 일 |
| POST | `/plans/{planId}/activate` | 이 계획을 사용 중으로 전환 |
| DELETE | `/plans/{planId}` | 계획 삭제 (학습기록이 연결돼 있으면 400) |
| GET | `/replan` | 밀렸는지와 다시 짠 일정 미리보기 |
| POST | `/replan/accept` | 다시 짠 일정을 새 계획으로 저장하고 사용 |
| POST | `/replan/dismiss` | 추천 거절 (7일 동안 다시 묻지 않음) |

계획 요청(`preview`, `preview-chat`, `save`)에는 `weekdayMinutes`(`{"1":60,"6":240}`, 요일 번호 → 분)를 추가했습니다. 값이 없으면 예전처럼 `dailyMinutes`와 `studyWeekdays`로 계산합니다.
